# Pi Local Policy 架构

[English](../../architecture.md) | [Русский](../ru/architecture.md) | **简体中文**

本文介绍当前实现，而非适用于 Pi 所有功能的通用沙箱机制。兼容性依赖已验证的 SDK 版本。安装和使用流程见 [README.md](README.md)，信任模型见 [SECURITY.md](SECURITY.md)。

## 调用路径

```text
用户任务
        ↓
Pi 主模型
        ↓
工具调用 / local_codemode 嵌套调用
        ↓
tool_call：名称 + 注册来源 + 参数
        ├── 未知或禁止 → 错误
        ├── 受信任的搜索来源 → 自动运行外部处理器
        ├── 获准的外部工具 → 确认一次调用
        └── 获准的本扩展工具
                 ├── 文件操作 → Seatbelt 中的 fs-worker
                 ├── bash → Seatbelt 中的进程，无网络
                 ├── network_bash → 确认 → 带网络的 Seatbelt
                 └── web_fetch → 受限制的公开 HTTP(S) GET
```

图中不包含 Pi 自身代码或第三方扩展代码的任意操作：它们属于系统的受信任部分。

## 1. 调用和工具来源检查

`src/index.ts` 注册本扩展的工具及 `tool_call` 处理器。`src/policy.mjs` 检查工具名称及注册该工具的文件精确路径。仅名称为 `bash` 并不够：必须使用本扩展提供的预期处理器。

这样可以在名称冲突时拒绝执行。此检查不验证磁盘上文件是否保持不变，也不隔离第三方扩展。

对于文件工具，还会检查路径。对于 `bash`，会检查一些明确禁止的命令形式。检查处理器出现错误会转化为阻止执行。未知工具不会自动获得访问权限。

命令文本检查属于辅助手段。它不是完整 shell 解析器，也不试图证明任意脚本安全。本扩展命令及其子进程的实际访问限制由 macOS Seatbelt 配置实施。

## 2. 路径与工作区

路径会转换为绝对路径，并解析已有符号链接。对于尚不存在的文件，会检查最近的已存在父目录。原始路径和解析后的路径都会被检查。

项目、临时区域及额外获准的根目录允许读取普通数据。写入仅允许在项目和临时区域中进行。已知敏感信息路径不受一般授权影响，始终被排除。禁止写入 `.git`、智能体目录和已知指令文件。

除用户资料外，受信任只读根目录还包括扩展文件、Pi 的技能和扩展目录、必要运行时目录，以及已登记的命令完整输出文件。配置本身允许读取必要的系统和工具目录。这并不承诺隐藏整个文件系统或其元数据。

会话根目录和额外授权会写入 Pi 分支的 custom entry。重新加载后，会读取当前分支最新的适用记录。

持久配置从 `<agent-dir>/local-policy.json` 读取。文件存在时，它会完整替代相邻的软件包或旧版 `config.json`，不会合并。持久文件格式错误会阻止执行，而非退回默认值。npm 软件包加载 `src/index.ts`；手动安装使用扁平运行时目录。两种方式均使用同一配置目录位置，因此软件包更新后用户授权可以保留。配置属于用户控制的受信任输入。

可选的 `readTools` 仅接受 `web_search` 的精确来源映射，允许经过检查的宿主处理器在 Seatbelt 之外自动执行。`askTools` 映射外部工具的精确来源，每次调用都需通过 UI 确认。两种映射都不会隔离外部扩展。

## 3. 文件操作

在可行的情况下，使用 Pi 标准工具定义以保持参数和结果兼容。由通过 `runSandbox` 启动的 `src/fs-worker.mjs` 读取和写入文件内容；JSON 输入通过 stdin 传递。预先路径检查并非唯一限制：在实际操作发生时，系统策略也同时生效。

`grep` 和 `find` 在 Seatbelt 内运行 ripgrep。可执行文件仅从 `<agent-dir>/bin/rg` 和固定的 Homebrew/系统路径解析；缺少时会报告错误，不会自动下载。跳过受保护文件产生的错误不会被当作目标数据不存在的证据：搜索结果可能不完整。`ls` 根据读取规则过滤条目。

## 4. 进程与临时目录

`src/sandbox.mjs` 生成默认拒绝的配置，然后允许必要的进程操作、读取获准根目录、写入项目和临时区域，以及访问有限系统资源。受保护路径的显式禁止规则优先于一般授权。

每次调用都会创建新的临时工作目录，并使用独立的 `HOME`、`TMPDIR`、XDG 目录和 npm 缓存。目录结构由项目外的受信任代码创建；先前可运行的进程不应能通过符号链接控制新的父目录。会话先前的临时结果可供读取，但不会成为新的共享可写区域。

环境根据允许列表创建。不会继承用户 shell 配置、API 密钥、SSH agent、`NODE_OPTIONS`、`BASH_ENV` 和加载器环境变量。Git 不会获得常规系统和用户配置，并禁用交互式凭据提示。

通过 `/bin/bash --noprofile --norc` 启动。取消和超时会终止整个进程组。初始化失败时没有绕过 Seatbelt 的替代启动方式。保存的输出大小有限制，但并未提供完整的 CPU、RAM 或磁盘配额系统。

进程可以运行配置规则允许访问的可执行文件。隔离并不意味着只允许预先列出的安全程序。

## 5. 网络与确认

普通 `bash` 禁止联网。`network_bash` 会在启动前于 Pi 界面显示命令。确认不会保存用于以后的调用；对话框串行处理。没有 UI、取消、对话框超时，或在参数中发现秘密，都会导致拒绝执行。

确认后会为进程及其后代启用网络，包括本地和私有地址。其他限制保持不变。这是允许命令联网执行，并非批准以后每一次 HTTP 请求。进程可以发送它能读取的数据。宿主凭据不会被专门提供。

对于 `askTools` 中受信任的外部工具，确认仅针对其自身处理器的一次调用。这些处理器不在本扩展的 Seatbelt 中运行。特别是浏览器操作拥有已安装浏览器扩展自身的权限。

## 6. 公开页面获取

`src/public-fetch.mjs` 使用 HTTP(S) GET，不携带用户自定义请求头、cookies、身份验证信息、代理，也不复用连接。连接前先检查 URL。所有 DNS 响应都必须是允许的公开地址；通过具体请求的 `lookup` 固定连接地址。每次重定向都会重新进行相同流程。

获取有整体超时、响应大小和重定向次数限制。仅支持有限的文本 MIME 类型。HTML 通过简化转换清理，不执行 JavaScript。这不是完整浏览器或通用文档解析器。

检查限制请求目标，但不验证返回内容的真实性。页面文本仍是提供给模型的不可信源数据。

## 7. Codemode

经验证的 Pi 版本中，标准 codemode 提供辅助 `models` 命名空间。本扩展使用 `models: false` 创建它，并以 `local_codemode` 名称注册。

可用嵌套工具不包含标准 `codemode`，也不允许递归调用 `local_codemode`。嵌套调用交由原生 `ctx.executeTool` 执行，以保留 `tool_call` 路径和访问规则。标准 `codemode` 还会被策略处理器禁止，并从活动工具中移除。

这不会禁止 Pi 的主模型调用，而是移除 codemode 中另一条辅助模型调用路径。

## 8. 测试覆盖内容

- 路径、符号链接、受保护名称和根目录的决策。
- 工具名称和来源的决策、冒充本扩展工具的情况，以及显式信任的搜索来源。
- 环境和 Seatbelt 配置生成。
- 使用模拟 DNS 和 HTTP 获取公开页面：地址、重定向、取消、超时、响应大小和类型。
- 使用真实 Pi 加载器加载扩展，经由 ExtensionRunner 处理及常规工具分发。
- 不调用模型的 codemode 嵌套调用检查。
- 在 macOS 单独运行时，实际检查读取、写入、秘密哨兵文件、符号链接、网络禁用、子进程、取消，以及普通工作流程。

测试不能替代独立审计，不覆盖任意恶意扩展代码，也不能证明 macOS 或 Pi 不存在漏洞。
