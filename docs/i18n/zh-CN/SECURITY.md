# 安全与信任模型

[English](../../../.github/SECURITY.md) | [Русский](../ru/SECURITY.md) | **简体中文**

Pi Local Policy 是适用于 macOS 的实验性模型工具限制层。项目尚未经过独立安全审计。测试结果描述的是已验证的场景，并不能证明不存在绕过方式。

## 已验证版本

当前兼容性目标为 `@earendil-works/pi-coding-agent` **1.0.3**、Node.js **22.19+**，以及具有 `/usr/bin/sandbox-exec` 的 macOS。其他 Pi 版本、Linux 和 Windows 不属于受支持运行环境。macOS 可能限制或改变 Seatbelt 的可用性；初始化失败时会阻止执行。

## 受限制的范围

- 按名称、注册来源、路径和操作类型检查模型工具调用。
- 受控文件操作和进程在默认拒绝的 Seatbelt 配置下运行。
- 写入仅允许在所选项目和当前临时区域内进行，并额外排除控制文件和已知敏感信息路径。
- 普通进程无法联网，也不会获得大多数宿主环境变量；子进程继承这些限制。
- `local_codemode` 的嵌套调用经过相同检查路径。
- 公开页面获取会检查 DNS 和重定向，并固定已验证的连接地址。
- 检查失败、未知工具、用户拒绝，或需要确认但没有 UI 时，都不会退回无限制模式。

## 仍受信任的部分

Pi、Node.js、macOS、已安装扩展的代码和用户配置仍受信任。该扩展不隔离整个 Pi 进程：任意扩展都可能在加载时、处理器中或常规工具调用路径之外执行自身代码。

精确源路径检查不等于检查扩展内容。获准的 `web_search`（包括通过 `readTools` 配置的来源）、浏览器和 `askTools` 由各自的宿主代码执行，不会自动获得本扩展 `bash` 的文件隔离。用户的 `!` 命令也仍属于用户自身的操作。

## 重要限制

- 选择项目即授权对普通文件进行无需确认的修改和删除。限制范围不能替代备份。
- 禁止根目录列表无法识别所有重要文件夹。请选择独立工作目录，启动后检查 `Root`，并避免授予过于宽泛的只读权限。
- 秘密保护基于已知路径和部分值格式。普通文档中的密钥可能仍可访问。读取文件元数据的权限比读取内容的权限更广。
- 获准的 `network_bash` 拥有网络访问权限，包括本地网络，并可以发送它能访问的项目资料或只读根目录中的资料。命令确认不会分析每一次后续请求。
- 公开 GET 和搜索请求会向相应服务暴露 URL 或查询内容；GET 本身也不保证服务器端没有副作用。
- 此策略不会消除第三方程序的错误、网页和资料中的恶意指令、研究准确性问题，或主模型费用。
- 临时工作区不会自动清理。项目数据和合成测试文件可能留在用户临时目录中。
- 持久 `<agent-dir>/local-policy.json` 授权及软件包回退配置属于受信任输入。`readTools` 仅允许指定精确来源的 `web_search`，但来源路径检查既不是代码审计，也不是操作系统限制。
- 安装程序是受信任的用户脚本。其路径检查不能防御另一个宿主进程同时修改安装文件。

## 报告问题

请先使用不含真实密钥、个人数据或他人资料的合成文件复现问题。注明 macOS、Node 和 Pi 版本、预期限制、调用的工具，以及最小复现步骤。

对于可复现的边界绕过问题，如仓库已启用相关功能，请使用[私密漏洞报告](https://github.com/happyer29/pi-local-policy/security/advisories/new)。否则，请通过项目可用的联系方式与维护者商定私密沟通渠道。目前尚未公布专用安全邮箱。不要将真实令牌、身份验证设置内容或私人会话附加到公开 issue。

安装和使用说明见 [README.md](README.md)。
