# Безопасность и модель доверия

[English](../../../.github/SECURITY.md) | [Русский](SECURITY.md) | [简体中文](../zh-CN/SECURITY.md)

Русский перевод; [основная версия на английском](../../../.github/SECURITY.md).

Pi Local Policy — экспериментальный слой ограничений для инструментов модели на macOS. Проект не проходил независимый аудит безопасности. Результаты тестов описывают проверенные сценарии, а не доказывают отсутствие обходов.

## Проверяемая версия

Текущая цель совместимости — `@earendil-works/pi-coding-agent` **1.0.3**, Node.js **22.19+**, macOS с `/usr/bin/sandbox-exec`. Иные версии Pi, Linux и Windows не считаются поддержанными средами выполнения. macOS может ограничивать или изменять доступность Seatbelt; при ошибке инициализации выполнение блокируется.

## Что ограничивается

- Вызовы инструментов модели проверяются по имени, источнику регистрации, пути и типу действия.
- Контролируемые файловые операции и процессы запускаются под deny-default профилем Seatbelt.
- Запись разрешена в выбранном проекте и текущей временной области с дополнительными исключениями для управляющих файлов и известных путей с секретами.
- Обычные процессы не получают сеть или большинство переменных окружения хоста; дочерние процессы наследуют ограничения.
- Вложенные вызовы `local_codemode` проходят тот же путь проверок.
- Публичная загрузка проверяет DNS и перенаправления и фиксирует проверенный адрес соединения.
- Ошибка проверки, неизвестный инструмент, отказ пользователя или отсутствие UI для требуемого подтверждения не переводятся в неограниченный режим.

## Что остаётся доверенным

Pi, Node.js, macOS, код установленных расширений и конфигурация пользователя остаются доверенными. Это расширение не изолирует весь процесс Pi: произвольное расширение может выполнить собственный код при загрузке, в обработчике или вне обычного пути инструментов.

Проверка точного source path не является проверкой содержимого расширения. Разрешённые `web_search` (включая источник из `readTools`), браузер и `askTools` исполняются своим host-кодом и не получают файловую изоляцию нашего `bash` автоматически. Пользовательские `!`-команды также остаются действиями самого пользователя.

## Существенные ограничения

- Выбранный проект является разрешением на изменение и удаление обычных файлов без подтверждения. Ограничение области не заменяет резервную копию.
- Список запрещённых корней не распознаёт все ценные папки. Выбирайте отдельный рабочий каталог, проверяйте `Root` после запуска и не выдавайте широкие read grants.
- Защита секретов основана на известных путях и некоторых форматах значений. Ключ в обычном документе может остаться доступным. Чтение метаданных файлов разрешено шире чтения их содержимого.
- Одобренный `network_bash` получает сетевой доступ, включая локальную сеть, и может отправлять доступные ему материалы проекта или read roots. Подтверждение команды не анализирует каждый её последующий запрос.
- Публичные GET и поисковые запросы раскрывают URL или запрос соответствующему сервису; GET сам по себе не гарантирует отсутствие побочных эффектов на сервере.
- Ошибки в сторонних программах, вредоносные инструкции из веба и источников, точность исследования и стоимость основной модели не устраняются этой политикой.
- Временные рабочие области не очищаются автоматически. Данные проекта и синтетические тестовые файлы могут оставаться в пользовательском временном каталоге.
- Постоянные разрешения `<agent-dir>/local-policy.json` и резервная конфигурация пакета — доверенные данные. `readTools` допускает только `web_search` с явно указанным источником, но проверка пути не является аудитом кода или ограничением операционной системы.
- Установщик — доверенный пользовательский скрипт. Его проверки путей не являются защитой от другого host-процесса, одновременно изменяющего файлы установки.

## Сообщение о проблеме

Сначала воспроизведите проблему на синтетических файлах без настоящих ключей, личных данных и чужих материалов. Укажите версии macOS, Node и Pi, ожидаемое ограничение, вызванный инструмент и минимальные шаги воспроизведения.

Для воспроизводимого обхода границ используйте [приватное сообщение об уязвимости](https://github.com/happyer29/pi-local-policy/security/advisories/new), если эта возможность включена в репозитории. Иначе согласуйте приватный канал с сопровождающим через доступные контакты проекта. Выделенный адрес безопасности пока не объявлен. Не прикладывайте настоящие токены, содержимое настроек авторизации и приватные сессии к публичному issue.
