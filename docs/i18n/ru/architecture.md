# Устройство Pi Local Policy

[English](../../architecture.md) | [Русский](architecture.md) | [简体中文](../zh-CN/architecture.md)

Русский перевод; [основная версия на английском](../../architecture.md).

Этот документ описывает текущую реализацию, а не универсальный механизм sandbox для всех возможностей Pi. Совместимость привязана к проверенной версии SDK. Общие сценарии установки и использования находятся в [README на русском](README.md), модель доверия — в [правилах безопасности](SECURITY.md).

## Путь вызова

```text
Задание пользователя
        ↓
Основная модель Pi
        ↓
Вызов инструмента / вложенный вызов local_codemode
        ↓
tool_call: имя + источник регистрации + аргументы
        ├── неизвестный или запрещённый → ошибка
        ├── доверенный источник поиска → автоматический внешний обработчик
        ├── разрешённый внешний инструмент → подтверждение одного вызова
        └── разрешённый собственный tool
                 ├── файловая операция → fs-worker в Seatbelt
                 ├── bash → процесс в Seatbelt без сети
                 ├── network_bash → подтверждение → Seatbelt с сетью
                 └── web_fetch → ограниченный публичный HTTP(S) GET
```

Диаграмма не охватывает произвольные действия кода самого Pi и сторонних расширений: они находятся в доверенной части системы.

## 1. Проверка вызовов и источника инструмента

`src/index.ts` регистрирует собственные инструменты и обработчик `tool_call`. `src/policy.mjs` проверяет имя инструмента и точный путь файла, из которого он зарегистрирован. Одного совпадения имени `bash` недостаточно: должен использоваться ожидаемый обработчик из этого расширения.

Это позволяет отказаться от выполнения при конфликте имён. Такая проверка не удостоверяет неизменность файла на диске и не изолирует сторонние расширения.

Для файловых инструментов дополнительно проверяется путь. Для `bash` проверяются некоторые явно запрещённые формы команд. Ошибка обработчика проверки превращается в блокировку. Неизвестный инструмент не получает доступ автоматически.

Проверки текста команды — вспомогательные. Они не являются полным парсером shell и не пытаются доказать безопасность любого скрипта. Фактическое ограничение доступа собственных команд и их дочерних процессов обеспечивает профиль macOS Seatbelt.

## 2. Пути и рабочая область

Пути приводятся к абсолютному виду с разрешением существующих симлинков. Для ещё не существующего файла проверяется ближайший существующий родитель. Проверяется и исходный путь, и разрешённый путь.

Чтение обычных данных допускается в проекте, временной области и дополнительных разрешённых корнях. Запись — в проекте и временной области. Известные пути с секретами исключаются независимо от общих разрешений. Запись в `.git`, каталоги агента и известные файлы инструкций запрещена.

Кроме пользовательских источников, доверенные корни чтения включают файлы расширения, каталоги навыков и расширений Pi, необходимые runtime-каталоги и зарегистрированные файлы полного вывода команд. Сам профиль допускает чтение необходимых системных и инструментальных каталогов. Это не обещание скрыть всю файловую систему или её метаданные.

Сессионные корень и дополнительные разрешения записываются в custom entry ветки Pi. После перезагрузки читается последняя подходящая запись текущей ветки.

Постоянная конфигурация профиля читается из `<agent-dir>/local-policy.json`. Если файл есть, он целиком заменяет соседний пакетный или прежний `config.json`, без объединения. Некорректный постоянный файл блокирует выполнение вместо возврата к значениям по умолчанию. npm-пакет загружает `src/index.ts`; ручная установка использует папку без вложенного `src/`. Оба варианта используют одинаковый путь конфигурации профиля, поэтому пользовательские разрешения сохраняются при обновлениях пакета. Конфигурация — доверенные данные пользователя.

Необязательный `readTools` принимает только точное сопоставление источника `web_search`, разрешая проверенному обработчику автоматически исполняться в процессе Pi вне Seatbelt. `askTools` сопоставляет точные источники внешних инструментов; каждый вызов требует подтверждения через UI. Ни один вариант не изолирует внешнее расширение.

## 3. Файловые операции

Стандартные определения инструментов Pi используются для совместимости параметров и результата там, где это возможно. Содержимое файлов читает и записывает `src/fs-worker.mjs`, запущенный через `runSandbox`; JSON-вход передаётся через stdin. Предварительная проверка пути сама по себе не является единственным ограничением: системная политика действует и в момент фактической операции.

`grep` и `find` запускают ripgrep внутри Seatbelt. Исполняемый файл ищется только в `<agent-dir>/bin/rg` и фиксированных путях Homebrew/системы; при отсутствии выводится ошибка без автоматического скачивания. Ошибки из-за пропущенных защищённых файлов не выдаются за доказательство отсутствия искомых данных: результат поиска может быть неполным. `ls` фильтрует элементы по правилам чтения.

## 4. Процессы и временные каталоги

`src/sandbox.mjs` строит профиль с запретом по умолчанию. Затем разрешаются необходимые операции процесса, чтение разрешённых корней, запись проекта и временной области, ограниченные системные ресурсы. Явные запреты защищённых путей действуют поверх общих разрешений.

Для каждого вызова создаётся новый рабочий временный каталог с отдельным `HOME`, `TMPDIR`, XDG-каталогами и npm-кэшем. Структура создаётся доверенным кодом вне проекта; старые доступные процессы не должны управлять новыми родительскими каталогами через симлинки. Предыдущие временные результаты сессии доступны для чтения, но не становятся новой общей областью записи.

Окружение создаётся по разрешённому списку. Пользовательские конфигурации оболочки, API-ключи, SSH agent, `NODE_OPTIONS`, `BASH_ENV` и переменные загрузчика не наследуются. Git не получает обычную системную и пользовательскую конфигурацию, а интерактивный запрос учётных данных отключён.

Запуск происходит через `/bin/bash --noprofile --norc`. Отмена и тайм-аут завершают группу процессов. Нет альтернативного запуска без Seatbelt при ошибке инициализации. Ограничивается размер сохраняемого вывода, но полноценной системы CPU, RAM и дисковых квот нет.

Процессы могут запускать исполняемые файлы, доступные по правилам профиля. Изоляция не означает, что допускаются только заранее перечисленные безопасные программы.

## 5. Сеть и подтверждение

Обычный `bash` запускается с запретом сети. `network_bash` перед запуском показывает команду в интерфейсе Pi. Подтверждение не запоминается для будущих вызовов; диалоги сериализуются. Отсутствие UI, отмена, тайм-аут диалога и обнаруженные секреты в аргументах приводят к отказу.

После подтверждения включается сеть для процесса и его потомков, включая локальные и приватные адреса. Остальные ограничения сохраняются. Это разрешение на сетевое выполнение команды, а не одобрение каждого будущего HTTP-запроса. Процесс может отправить читаемые им данные. Учётные данные хоста специально не предоставляются.

Для доверенных внешних инструментов из `askTools` подтверждается один вызов их собственного обработчика. Такие обработчики не выполняются в Seatbelt этого расширения. В частности, действия браузера имеют собственные полномочия установленного browser-расширения.

## 6. Публичная загрузка

`src/public-fetch.mjs` использует HTTP(S) GET без пользовательских заголовков, cookies, авторизации, прокси и повторно используемых соединений. URL проверяется до подключения. Все DNS-ответы должны быть допустимыми публичными адресами; адрес соединения фиксируется в `lookup` конкретного запроса. Каждое перенаправление проходит тот же процесс заново.

У загрузки есть общий тайм-аут, ограничение размера ответа и числа перенаправлений. Поддерживаются ограниченные текстовые MIME-типы. HTML очищается упрощённым преобразованием, без исполнения JavaScript. Это не полноценный браузер или универсальный парсер документов.

Проверки ограничивают назначения запросов, но не достоверность возвращаемого содержимого. Текст страницы по-прежнему является недоверенными исходными данными для модели.

## 7. Codemode

Стандартный codemode проверенной версии Pi предоставляет вспомогательный namespace `models`. Для этого расширения он создаётся с `models: false` и регистрируется под именем `local_codemode`.

Доступные вложенные инструменты исключают стандартный `codemode` и рекурсивный `local_codemode`. Выполнение вложенных вызовов передаётся штатному `ctx.executeTool`, чтобы сохранить путь `tool_call` и правила доступа. Стандартный `codemode` дополнительно запрещается обработчиком политики и исключается из активных инструментов.

Это не запрет основных вызовов модели Pi. Это удаление отдельного вспомогательного пути вызова моделей из codemode.

## 8. Что проверяют тесты

- Решения по путям, симлинкам, защищённым именам и корням.
- Решения по именам и источникам инструментов, подмена собственного инструмента и явные доверенные источники поиска.
- Окружение и генерация профиля Seatbelt.
- Загрузка публичных страниц через имитированные DNS и HTTP: адреса, перенаправления, отмена, тайм-ауты, размер и тип ответа.
- Загрузка расширения настоящим загрузчиком Pi, обработка через ExtensionRunner и обычный tool dispatch.
- Проверки вложенных вызовов codemode без обращения к модели.
- При отдельном запуске на macOS — реальные чтение, запись, секреты-сентинелы, симлинки, запрет сети, дочерние процессы, отмена и обычный рабочий сценарий.

Тесты не заменяют независимый аудит, не покрывают произвольный вредоносный код расширений и не доказывают отсутствие уязвимостей macOS или Pi.
