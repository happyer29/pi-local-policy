# Участие в разработке

[English](../../../.github/CONTRIBUTING.md) | [Русский](CONTRIBUTING.md) | [简体中文](../zh-CN/CONTRIBUTING.md)

Русский перевод; [основная версия на английском](../../../.github/CONTRIBUTING.md).

Обсуждайте изменения относительно поведения инструментов и их границ: автоматическое выполнение, подтверждение одного вызова или блокировка. Изменение разрешений должно иметь пример того, что станет доступно пользователю, и что останется запрещено.

Английский — основной язык документации и сообщений расширения; английские документы служат исходной версией. При изменении оригиналов обновляйте русские и китайские переводы по ссылкам выше. Переводы документации не означают наличие переключателя языка во время выполнения.

## Локальная проверка

```sh
npm ci --ignore-scripts
npm test
npm run check:release
npm run check:package
```

На macOS дополнительно:

```sh
npm run test:sandbox
```

Pi для нативных интеграционных тестов берётся из dev-зависимости или `PI_CODING_AGENT_ROOT`. Пропуск тестов из-за отсутствующего SDK не подтверждает совместимость. Настроенный, но сломанный SDK должен давать ошибку. Реальные тесты Seatbelt требуют разрешённого запуска `sandbox-exec` без запрещающей его внешней песочницы.

Используйте только временные каталоги и искусственные секреты. Тесты не должны обращаться к модели, публиковать данные, использовать авторизацию пользователя или менять действующую установку Pi.

## Области кода

- `src/policy.mjs`: чистые решения по путям, инструментам и отдельным шаблонам команд.
- `src/sandbox.mjs`: профиль Seatbelt, очищенное окружение, дочерние процессы и ограничения выполнения.
- `src/index.ts`: Pi API, регистрация и проверка инструментов, UI подтверждения, сессионные настройки.
- `src/public-fetch.mjs`: публичный HTTP(S), DNS, редиректы, размер и время загрузки.
- `scripts/management.mjs`: установка и удаление с планом изменений и резервными копиями.

Новый инструмент не следует молча разрешать по одному имени. Опишите источник регистрации, доступные ему ресурсы, поведение без UI и путь вложенного вызова. Изменение безопасности сопровождайте проверкой значимой границы, а не только повторением реализации.

Согласуйте README, модель доверия и тесты с фактическим поведением. Не заявляйте защиту от всех обходов или совместимость с непроверенными версиями. При добавлении файла обновите явный список публикации в `scripts/check-release.mjs`.

Публикация выполняется вручную; CI запускает проверки на macOS и не публикует автоматически. Перед выпуском проверьте список файлов `npm pack --dry-run`, выполните `npm run check:release`, полный набор тестов на поддерживаемой macOS и установку упакованного артефакта в новом профиле. Личные разрешения храните в `<agent-dir>/local-policy.json`, вне содержимого пакета. Учётные данные и локальные настройки не должны попадать в пакет. См. [SECURITY.md](SECURITY.md) для сообщений о проблемах безопасности.
