# Pi Local Policy

[![Версия npm](https://img.shields.io/npm/v/pi-local-policy)](https://www.npmjs.com/package/pi-local-policy)

[English](../../../README.md) | [Русский](README.md) | [简体中文](../zh-CN/README.md)

Полный русский перевод документации. Основная версия — [на английском](../../../README.md); сообщения расширения по умолчанию используют английский. Названия инструментов, команды и ключи конфигурации сохраняют исходное написание. Переводы не добавляют отдельную настройку языка во время выполнения.

Локальные правила доступа для [Pi Coding Agent](https://pi.dev/): обычная работа в проекте выполняется автоматически, отдельные внешние действия требуют подтверждения, неизвестные инструменты блокируются.

Расширение проверяет реальные вызовы инструментов с помощью кода. Модель не вызывается для принятия решений о доступе. Для файловых операций и команд используется изоляция macOS Seatbelt через `sandbox-exec`.

**Статус: экспериментальная версия для macOS.** Это дополнительный слой ограничений для инструментов модели, а не виртуальная машина или гарантия защиты от всех способов обхода. Pi и установленные расширения остаются доверенным кодом. Перед использованием прочитайте [границы защиты](#границы-защиты) и [SECURITY.md](SECURITY.md).

## Для чего это нужно

Pi может самостоятельно читать материалы, создавать отчёты, запускать локальную обработку данных и тесты. При этом не требуется подтверждать каждый пайп или каждое чтение файла.

Пример задачи:

> Исследуй подходы к оценке исследовательских агентов по публичным текстовым источникам. Сохрани источники в sources.md, сравнение подходов — в comparison.md, выводы и открытые вопросы — в report.md. Для каждого существенного вывода укажи источник.

Если поиск доступен и материалы представлены обычными текстовыми страницами, этот сценарий может пройти без диалогов подтверждения. Установка пакетов из сети, использование браузера и подключение новых инструментов имеют другие правила.

Расширение не устанавливает Jev и не использует его для проверки команд. Основная модель Pi, сервис поиска и другие подключённые сервисы могут по-прежнему расходовать API или деньги.

## Правила по умолчанию

| Действие | Поведение |
| --- | --- |
| Чтение, поиск, создание и редактирование обычных файлов проекта | Автоматически |
| Локальные команды, пайпы, обработка данных и тесты | Автоматически, в Seatbelt, без сети |
| Чтение дополнительно разрешённой папки | Автоматически, только чтение |
| Загрузка публичной текстовой страницы через `web_fetch` | Автоматически, без входа и cookies |
| Поиск через поддерживаемое расширение `web_search` | Автоматически, если оно установлено отдельно |
| Одна команда с сетью через `network_bash` | Подтверждение конкретного вызова |
| Поддерживаемое действие браузера | Подтверждение каждого вызова |
| Неизвестный инструмент, в том числе MCP или подагент | Блокировка |
| Чтение известных путей с секретами | Блокировка |
| Запись вне проекта и временной рабочей области | Блокировка |
| Изменение `.git`, `.pi`, `.agents` и защищённых файлов инструкций | Блокировка |
| Явно распознанные системные, привилегированные и разрушительные Git-команды | Блокировка |

**Обычные файлы внутри проекта можно менять и удалять без подтверждения.** Расширение ограничивает область доступа, но не оценивает ценность каждой правки. Используйте отдельную рабочую копию и резервные копии для важных материалов.

## Требования

- macOS с доступным `/usr/bin/sandbox-exec`.
- Pi из пакета `@earendil-works/pi-coding-agent` версии **1.0.3**. Совместимость с другими версиями пока не заявлена: используются API расширений и codemode этой версии.
- Node.js **22.19 или новее**; исходная проверка выполнена на Node.js **24.15.0**.
- Существующая отдельная папка проекта.
- Для `grep` и `find` — бинарный файл ripgrep в `<agent-dir>/bin/rg`, `/opt/homebrew/bin/rg`, `/usr/local/bin/rg` или `/usr/bin/rg`. В новом профиле Pi его может не быть: установите отдельно, например `brew install ripgrep`. Расширение не скачивает его автоматически и не ищет через унаследованный `PATH`.

Linux и Windows не поддерживаются. Если Seatbelt не запускается, файловые операции и команды не переводятся в обычный неограниченный режим.

`web_search` и инструменты браузера **не входят в этот репозиторий**. Политика распознаёт их по имени и пути исходного расширения. Без соответствующего расширения эти возможности не появятся. Подробности — в [настройке дополнительных инструментов](#дополнительные-инструменты).

## Установка

Установите пакет через менеджер пакетов Pi на поддерживаемом Mac:

```sh
pi install npm:pi-local-policy@0.1.0
```

Это пакет сообщества Pi из npm. Он не сопровождается официальной командой Pi и не проходил независимый аудит безопасности. Ключевое слово `pi-package` позволяет обнаруживать пакет в [каталоге Pi](https://pi.dev/packages).

**Используйте только один источник установки.** Если прежняя копия загружается из `<agent-dir>/extensions/local-policy`, удалите её до добавления npm-пакета. Для копии, управляемой скриптом этого репозитория, используйте процедуру удаления ниже. Неуправляемую копию сначала сохраните, затем уберите её регистрацию и автоматически обнаруживаемую папку расширения. Не загружайте ручную копию и npm-пакет одновременно.

Перед перезагрузкой отключите расширения, которые регистрируют те же инструменты или самостоятельно подтверждают те же действия. В частности, отключите существующие `bash-guard` и исходный `web-fetch`: пакет предоставляет собственный `web_fetch`. Отдельно проверьте Jev и другие обработчики подтверждений. **`pi install` не меняет эти настройки.** Дублирующие регистрации и обработчики могут блокировать инструменты или добавлять диалоги.

Каталог агента берётся из `PI_CODING_AGENT_DIR`, если переменная задана, иначе из `~/.pi/agent`. Для отдельного профиля используйте одинаковое значение при установке и запуске Pi. Установка пакета не создаёт проект и не открывает доступ ко всей домашней папке.

В Pi выполните:

```text
/reload
/local-policy
```

Проверьте `Root` и при необходимости выберите существующий отдельный проект:

```text
/local-policy root /absolute/path/to/project
/reload
/local-policy
```

При успешной проверке Seatbelt отображается `Local policy: AUTO`. `BLOCKED` означает, что нужно проверить сообщение об ошибке, рабочую папку, конфигурацию и доступность системной изоляции. До работы с важными материалами проверьте обычное чтение файла или локальную команду в пробном проекте.

### Необязательная ручная установка из исходников

В проверенной копии [репозитория исходников](https://github.com/happyer29/pi-local-policy) доступны локальные управляющие скрипты. Это альтернативный способ установки; не совмещайте его с npm в одном профиле.

Откройте терминал в корне репозитория, посмотрите план и примените его:

```sh
node scripts/install.mjs
node scripts/install.mjs --apply
```

Для отдельного профиля добавьте к обеим командам `--agent-dir /absolute/path/to/agent`. Сам аргумент не задаёт `PI_CODING_AGENT_DIR` для процесса Pi.

Установщик копирует исполняемые файлы в `<agent-dir>/extensions/local-policy`, сохраняет резервные копии и сведения об установке, регистрирует расширение в `settings.json` с сохранением остальных настроек. Он исключает стандартные пути `extensions/bash-guard/index.ts` и `extensions/web-fetch/index.ts`, а выбранный встроенный `codemode` в `defaultTools` заменяет на `local_codemode`. Другие обработчики требуют отдельной проверки. Исходные файлы исключённых расширений остаются на месте.

Если целевая папка содержит прежний неуправляемый `local-policy`, установщик архивирует его и сохраняет `config.json`. Реализации инструментов не объединяются. Повторная установка поверх управляемой версии запрещена. План показывает точные изменения; установщик не скачивает зависимости, не вызывает модели и не выполняет Git-операции. После установки выполните `/reload` и проверьте `/local-policy`.

## Выбор проекта и материалов

По умолчанию корень проекта берётся из рабочего каталога Pi. Относительные пути инструментов отсчитываются от выбранного корня.

Если Pi запущен из домашней папки или нужно работать в другом проекте:

```text
/local-policy root /absolute/path/to/project
/reload
/local-policy
```

Папка должна уже существовать. `/`, домашняя папка целиком, общие `Documents`, `Desktop`, `Downloads`, основные системные и общие инструментальные каталоги, папки учётных данных, конфигурации агента и `.git` не принимаются как рабочий проект. Подойдёт отдельная папка исследования внутри `Documents`.

Выбранный корень — доверенное разрешение на запись. Проверка не распознаёт все системные или ценные каталоги: выбирайте только отдельную рабочую папку проекта.

Дополнительные материалы можно подключить только для чтения:

```text
/local-policy allow-read /absolute/path/to/source-materials
```

Это не разрешает изменять подключённые материалы и не отменяет защиту известных путей с секретами. Выбирайте конкретные папки, необходимые для задачи.

Корень и разрешения `allow-read` сохраняются в ветке текущей сессии Pi и восстанавливаются после её перезагрузки. Это не глобальные разрешения для всех новых чатов. Отдельной команды отзыва одного `allow-read` сейчас нет; для чистого набора разрешений начните новую сессию.

Доступные команды:

| Команда Pi | Назначение |
| --- | --- |
| `/local-policy` | Показать состояние, корень и счётчики |
| `/local-policy status` | То же состояние |
| `/local-policy root /absolute/project` | Выбрать рабочий проект текущей сессии |
| `/local-policy allow-read /absolute/folder` | Добавить доступ только для чтения |

Это команды пользователя. Модель не может выдать себе разрешение через обычный вызов инструмента.

## Инструменты модели

Инструменты выбирает сам Pi по заданию. Обычно достаточно описать желаемый результат обычным текстом.

| Имя | Реализация и ограничения |
| --- | --- |
| `read` | Чтение разрешённых файлов через изолированный процесс; сохраняет поддержку распространённых изображений |
| `write`, `edit` | Запись и правки только в проекте и временной области; защищённые пути исключены |
| `grep`, `find`, `ls` | Поиск и просмотр разрешённых файлов; скрывают или пропускают защищённые пути |
| `bash` | `/bin/bash --noprofile --norc` в Seatbelt, без сети и пользовательских файлов запуска оболочки |
| `network_bash` | Та же файловая изоляция с сетью после подтверждения одного вызова |
| `web_fetch` | Публичный HTTP(S) GET с проверкой адресов и перенаправлений, без авторизации |
| `local_codemode` | Группировка вызовов инструментов; каждое вложенное действие проходит проверку |

Имена `read`, `write`, `edit`, `grep`, `find`, `ls`, `bash` и `web_fetch` заменяют стандартные реализации. Если одноимённый инструмент зарегистрирован другим расширением и источник не соответствует ожидаемому, политика блокирует его вместо запуска исходной реализации.

Встроенный `codemode` блокируется, поскольку в проверенной версии Pi он предоставляет вспомогательные API моделей вне обычного пути инструментов. `local_codemode` создаётся с `models: false`: группировка действий остаётся, прямой вспомогательный API моделей не предоставляется.

### Локальные команды

Примеры задач без подтверждений:

> Прочитай Markdown-файлы в проекте, найди противоречия и запиши список в findings.md.

> Обработай локальный CSV существующими инструментами и сохрани сводную таблицу в проекте.

> Запусти локальные тесты и исправь обнаруженную ошибку.

У процессов есть новый временный `HOME`, `TMPDIR` и каталоги кэша для каждого вызова. Большинство переменных окружения не передаётся. В частности, не передаются обычные API-ключи, SSH agent, настройки запуска оболочки и конфигурация Git пользователя. Команды могут отличаться от привычной пользовательской оболочки.

Зависимости, которым нужны существующие файлы вне разрешённых корней, пользовательский Python, вход в сервис или сеть, могут не заработать автоматически. Не следует считать любой сбой программы ошибкой политики. Сначала проверьте, какие ресурсы действительно нужны.

Сохраняйте конечные результаты в проекте: временные каталоги не являются долговременным хранилищем. Текущая версия не выполняет автоматическую очистку временных рабочих областей.

### Команда с сетью

Когда задача действительно требует сети из оболочки, модель может вызвать `network_bash`. Вы увидите конкретную команду, а разрешение действует только для этого вызова. Отказ, отмена или отсутствие интерфейса подтверждения означают, что команда не выполняется.

После разрешения сеть доступна всему процессу и его дочерним процессам, в том числе для обращения к локальным и приватным адресам. Файловые ограничения и очищенное окружение остаются в силе. **Разрешённая сетевая команда может передать по сети любые доступные ей материалы проекта или подключённых папок.** Подтверждение не является проверкой содержимого и назначения каждого сетевого запроса.

Обычные учётные данные компьютера не становятся доступны после подтверждения. Авторизованные публикации и деплой могут потребовать отдельного доверенного инструмента. Неограниченного обходного запуска в расширении нет.

### Публичные источники

`web_fetch` принимает публичные HTTP(S) URL на стандартных портах, проверяет DNS и каждое перенаправление. Адрес соединения фиксируется после проверки. Локальные, приватные и зарезервированные адреса, URL с логином, паролем или распознанными параметрами авторизации отклоняются.

Поддерживаются HTML, обычный текст, Markdown и JSON. Ограничения: до 2 MiB ответа, до пяти перенаправлений, 15 секунд на запрос. JavaScript страницы не исполняется. HTML преобразуется в упрощённый текст.

PDF, архивы, произвольные бинарные форматы и сжатые ответы сейчас не поддерживаются. Некоторые сайты требуют браузер или вход. Локальный PDF можно отдельно обрабатывать доступной программой в проекте, но встроенного исследовательского PDF-пайплайна здесь нет.

Запрос к публичной странице всё равно является сетевым обращением к стороннему сайту. Содержимое поискового запроса и URL не следует считать приватным каналом для секретных данных.

### Дополнительные инструменты

По умолчанию проверяются точные пути внутри каталога агента:

- `web_search` разрешён автоматически, если его источник — `extensions/web-search/index.ts`. Для другого проверенного пакетного пути требуется явное разрешение `readTools` ниже.
- `browser_goto`, `browser_eval`, `browser_console`, `browser_network`, `browser_fill`, `browser_click`, `browser_screenshot`, `browser_close` требуют подтверждения, если их источник — `extensions/browser/index.ts`.
- Стандартные инструменты Pi `ask_user_question` и `quiz` разрешены для общения с пользователем.
- Другие инструменты, включая MCP и подагентов, блокируются до явной настройки.

Проверка пути подтверждает источник регистрации, но не анализирует безопасность кода стороннего расширения. `web_search`, браузер и явно подключённые внешние инструменты исполняются своим доверенным расширением; файловая изоляция `bash` не переносится на них автоматически. Проверьте эти расширения до подключения.

Создайте или измените постоянную пользовательскую конфигурацию `<agent-dir>/local-policy.json` (обычно `~/.pi/agent/local-policy.json`). Храните личные разрешения здесь, чтобы обновления пакета их не перезаписывали:

```json
{
  "version": 1,
  "readRoots": [],
  "readTools": {},
  "askTools": {}
}
```

- `readRoots` добавляет постоянные разрешения на чтение для всех сессий профиля. Защищённые пути с секретами остаются исключёнными.
- `readTools` сейчас принимает только `web_search`, сопоставленный с точным абсолютным путём исходного расширения, и разрешает автоматический поиск. Это доверие к коду расширения в процессе Pi, **а не** изоляция или доказательство, что инструмент только читает. Используйте после проверки расширения. Например, поисковое расширение по нестандартному пакетному пути можно явно разрешить: `"readTools": { "web_search": "/absolute/path/to/reviewed/search/index.ts" }`. Другие имена в `readTools` не принимаются.
- `askTools` использует тот же формат точного имени и источника, но запрашивает подтверждение каждого вызова. Например: `"askTools": { "example_tool": "/absolute/path/to/reviewed/extension/index.ts" }`. Это пример формата; не добавляйте несуществующий инструмент. Конфликтующие разрешения не принимаются.

Постоянный файл используется как полная конфигурация, без объединения с пакетными значениями. Если его нет, читается соседний `config.json` (`src/config.json` в пакете или `config.json` прежней ручной установки без подпапки). Не храните новые личные разрешения внутри каталога npm-пакета. После редактирования выполните `/reload`. Неверная конфигурация вызывает блокировку, а не отключение правил.

## Границы защиты

Политика рассчитана на контроль действий модели через инструменты и проверенный путь вложенных вызовов codemode. Она не изолирует весь процесс Pi.

- **Доверяются Pi, установленным расширениям и пользовательской конфигурации.** Расширение с произвольным кодом может выполнять действия вне проверяемого пути. Проверка имени и источника инструмента не делает вредоносное расширение безопасным.
- **Команды пользователя через `!` — это пользовательская оболочка.** Они не становятся ограниченными командами модели.
- **Файловая система ограничена, содержимое не классифицируется полностью.** Секрет в обычном `notes.md` остаётся читаемыми данными проекта. Фильтры путей и некоторых форматов токенов не заменяют управление секретами.
- **Метаданные не скрыты полностью.** Seatbelt допускает чтение метаданных файлов для работы программ. Системные и инструментальные каталоги доступны для чтения по разрешённым правилам. Подробные корни перечислены в `src/sandbox.mjs`.
- **Подключённые материалы и веб-страницы могут содержать вредоносные инструкции.** Расширение не определяет достоверность источников и не устраняет prompt injection. Ограничения применяются к последующим вызовам инструментов.
- **Git защищён от записи.** `git status`, `diff`, `log` обычно доступны; `git add`, коммиты, смена ветки и другие операции записи в `.git` выполняйте вручную. Обычные файлы рабочей копии при этом могут изменяться.
- **Нет автоматического повышения прав.** Сбой Seatbelt, неразрешённый путь или неизвестный инструмент возвращают ошибку. Самостоятельного переключения на неограниченный исполнитель нет.

Более подробное устройство описано в [документе об устройстве расширения](architecture.md), порядок сообщения о проблемах и модель доверия — в [SECURITY.md](SECURITY.md).

## Обновление и удаление

Для npm-установки используйте менеджер пакетов Pi. README намеренно устанавливает закреплённую версию: проверьте следующий выпуск и установите его с явным номером (например, `pi install npm:pi-local-policy@0.1.1`, когда такой выпуск появится). Не запускайте ручной установщик поверх пакетной установки.

Чтобы удалить npm-пакет:

```sh
pi remove npm:pi-local-policy
```

Затем выполните `/reload`. Отдельно проверьте добавленные вами исключения конфликтующих расширений: удаление пакета их не отменяет. Пользовательский файл `<agent-dir>/local-policy.json` не удаляется вместе с пакетом. При необходимости сохраните или удалите его вручную.

### Удаление установки, управляемой скриптом

В проверенной копии исходников посмотрите и примените план:

```sh
node scripts/uninstall.mjs
node scripts/uninstall.mjs --apply
```

Для отдельного профиля добавьте к обеим командам `--agent-dir /absolute/path/to/agent`. Скрипты удаляют только собственную управляемую установку; они не удаляют npm-пакет или произвольные неуправляемые копии.

Удаление убирает регистрацию управляемого расширения и архивирует его файлы и конфигурацию. Поля `extensions` и `defaultTools` возвращаются к исходному состоянию только при совпадении соответствующего поля со снимком после установки. Если поле менялось позднее, удаляются только собственные ссылки `local-policy`/`local_codemode`, другие записи сохраняются и выводится предупреждение. Прежние исключения конфликтующих расширений могут потребовать ручной проверки.

Если установщик заменил существовавшую неуправляемую папку `local-policy`, удаление восстанавливает её из исходного архива. План показывает `restorePreviousExtension`; если архив утрачен, удаление останавливается. Резервные копии сохраняются. Затем выполните `/reload`.

Управляемую ручную установку нельзя обновлять поверх: сначала удалите её, затем проверьте новые исходники и установите их. При переходе на npm убедитесь, что прежняя папка расширения и её регистрация больше не загружаются, и только затем выполните `pi install`. До перехода перенесите проверенные прежние разрешения из архивного `config.json` в `<agent-dir>/local-policy.json`. Постоянная конфигурация имеет приоритет над пакетными или прежними значениями и сохраняется при обновлениях пакета.

## Разработка и тесты

Для разработки установите зависимости без запуска lifecycle-скриптов:

```sh
npm ci --ignore-scripts
npm test
```

В репозиторий включён `package-lock.json` для воспроизводимой установки зависимостей разработки. Семейство пакетов Pi SDK закреплено на проверенных версиях **1.0.3** для интеграционных тестов; используйте `npm ci`, чтобы сохранить этот набор зависимостей. Эти закрепления разработки не заменяют зависимости, поставляемые внутри установленного Pi.

`npm test` запускает переносимые тесты политик, публичной загрузки, генерации профиля и проверки расширения через настоящий загрузчик Pi. Сетевое поведение `web_fetch` проверяется имитациями DNS и HTTP; тесты не обращаются к моделям и не используют настоящие ключи.

Нативные тесты используют установленную dev-зависимость Pi. Для проверки конкретной внешней установки можно задать `PI_CODING_AGENT_ROOT` — абсолютный путь к каталогу пакета `@earendil-works/pi-coding-agent`. Если Pi не установлен, нативные интеграционные проверки пропускаются: такой запуск проверяет только доступную часть. Явно заданный, но неверный путь или несовместимый SDK должны приводить к ошибке.

На macOS дополнительно выполните реальные проверки Seatbelt:

```sh
npm run test:sandbox
```

Они проверяют файловые ограничения, синтетические секреты, симлинки, дочерние процессы, очистку окружения, запрет сети, отмену и обычный рабочий сценарий через инструменты Pi. Для них нужен разрешённый запуск `sandbox-exec`: дополнительная внешняя песочница может запретить вложенный Seatbelt.

Если тесты изоляции пропущены или среда запретила их запуск, это не подтверждает работу изоляции в этой среде. Успешные тесты также не являются доказательством отсутствия всех обходов.

Выпуски публикуются в npm вручную. CI запускает тесты и проверки состава, но не публикует автоматически. В npm-пакет по явному списку входят исполняемый код, документация, лицензия и необязательные управляющие скрипты; локальные пользовательские настройки и тестовые данные не включаются.

Перед подготовкой публикации выполните проверку состава:

```sh
npm run check:release
npm run check:package
```

## Состав репозитория

```text
pi-local-policy/
├── README.md                 # Главная страница на английском
├── LICENSE
├── package.json
├── src/                      # Исходники расширения и начальная конфигурация
├── scripts/                  # Установка, удаление и проверка состава публикации
├── tests/                    # Автоматические проверки
├── docs/
│   ├── architecture.md       # Архитектура на английском
│   └── i18n/
│       ├── ru/               # Полная документация на русском
│       └── zh-CN/            # Полная документация на упрощённом китайском
└── .github/                  # CI, политика безопасности и правила участия
```

Pi-пакет загружает `src/index.ts` и сохраняет структуру исходников. Необязательный ручной установщик копирует содержимое `src/` прямо в `<agent-dir>/extensions/local-policy/`, без вложенного `src/`. Команды управления исходной установкой и проверки выполняются из корня репозитория.

| Файл или каталог | Назначение |
| --- | --- |
| `src/index.ts` | Регистрация инструментов, обработчик вызовов, подтверждения и команды Pi |
| `src/policy.mjs` | Решения по путям, именам и источникам инструментов, некоторые проверки команд |
| `src/sandbox.mjs` | Профиль Seatbelt, окружение и запуск процессов |
| `src/fs-worker.mjs` | Файловые операции внутри изолированного процесса |
| `src/public-fetch.mjs` | Ограниченная публичная HTTP(S)-загрузка |
| `src/config.json` | Резервные значения пакета; личные разрешения хранятся в `<agent-dir>/local-policy.json` |
| `scripts/` | Локальная установка и удаление |
| `tests/` | Автоматические проверки |
| `README.md`, `.github/SECURITY.md`, `.github/CONTRIBUTING.md`, `docs/architecture.md` | Основная документация на английском |
| `docs/i18n/ru/` | Полный русский перевод документации, включая README |
| `docs/i18n/zh-CN/` | Полный перевод документации на упрощённый китайский, включая README |


Репозиторий не должен содержать пользовательские настройки Pi, сессии, API-ключи, локальные резервные копии или материалы исследований.
